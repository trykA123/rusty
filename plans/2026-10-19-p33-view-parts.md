# P33 · View parts: the user decides what each viewer shows

Status: ready · Repo: `<repo>` · Branch: `p33-vN` per atom · Started: 2026-10-19

## Goal

Every viewer opens calm and every optional part of it can be turned on or off: for the open file from a View menu (Alt+V) or the part's own key, and for good from the same menu ("Keep as default") or the settings sheet. Drawers open with the same keys everywhere. Implements D58 (owner, 2026-10-19: "the user should control what they see and how they see it").

Found by scouts on 2026-10-19: no viewer has view settings today; the only toggles are line ends (Alt+L), image details (I) and the Markdown preview split (Ctrl+Shift+V), none persisted; line numbers and the preview's folder summary are always on. `MenuItem.checked` already draws a check mark (`context_menu/row.rs:146`) but no Ferrite menu sets it. `SettingsStore::save_preserving_edits` writes one dotted key keeping comments. The automotive branch (`p16-b2`) adds the first `[automotive.view]` section with a `ViewPreset` enum and `Section::Automotive`; this plan builds on it.

## Decisions

Final. Workers never reopen them; a worker that finds one wrong stops and reports.

- **D1 — Settings shape.** Each viewer's parts live under `[<viewer>.view]` in `ferrite.toml`: `[text.view]`, `[image.view]`, `[markdown.view]`, `[preview.view]`, and (other branches) `[automotive.view]`, `[pdf.view]`. One shared `ViewPreset { Simple, Rich, Custom }` in rusty-store's settings module serves every viewer that has a `preset` key; `p16-b2`'s enum moves there.
- **D2 — Parts in this plan, defaults equal today's behaviour** (nothing changes for the owner on upgrade except the new menu):
  - text (read-only and editor): `line_numbers` (on), `line_ends` (off; Alt+L);
  - image: `details` (off unless the image view opens it today; Ctrl+I and I);
  - markdown: `preview_split` (today's default; Ctrl+Shift+V);
  - preview sheet (folder): `type_bars` (on), `largest_files` (on).
  Only viewers with at least two rich parts get a `preset` (automotive, PDF); the others show toggles only.
- **D3 — This file vs default.** A toggle from the View menu or a key changes only the open viewer and is forgotten when it closes. "Keep as default" writes that viewer's current parts to `ferrite.toml` (one `save_preserving_edits` per key, through the normal settings save path). "Reset to defaults" in the menu restores the open viewer to the settings' values. A settings change reaches open viewers live, except for parts the user changed in that viewer.
- **D4 — View menu.** Command `viewer.view_menu`, Alt+V in the Viewer context, plus a small "View" button at the top right of the viewer header (and of the preview sheet header). It is the existing `ContextMenu`; `MenuEntry::Run` gains a `checked` flag mapped to `MenuItem.checked`. Entries, in order: the preset choices (only when the viewer has a preset), one checked row per part with its key hint, a separator, "Keep as default", "Reset to defaults". The menu stays open after a toggle so several parts can be changed in a row; Esc closes it.
- **D5 — Drawer keys.** Commands `view.left_drawer` (Ctrl+B) and `view.right_drawer` (Ctrl+I) in the Viewer context; each kind maps them to its own drawer (automotive navigator / inspector, PDF pages-outline / hit list, image details on Ctrl+I as well as I). A kind without a drawer ignores them. Esc closes the topmost open drawer before it closes the viewer.
- **D6 — Settings sheet.** One section "Viewers" (icon from Lucide) with a group per viewer; each toggle row has a one-sentence hint saying what the part shows; Default/Changed and Reset come from the existing rows. Automotive's `Section::Automotive` from `p16-b2` becomes the Automotive group of this section.
- **D7 — Out of scope.** New parts that do not exist yet (wrap, minimap, hex column choices), per-folder or per-extension view memory, view profiles. Hex gets the shared menu with no parts until it has any.
