# P37 · PDF links and outline

Status: in progress · Repo: `<repo>` · Branch: `p37-*` · Started: 2026-10-20

## Goal

Links inside a PDF work: a click on an internal link goes to its page and position, a click on a web link opens the browser, and the keyboard can reach and follow every link. The Outline tab, which says "Ferrite cannot read PDF outlines yet", lists the document's chapters. The owner asked: links "that lead to certain chapters" do nothing today.

## Decisions

- **D1 — Link data comes from the helper.** `Request::Links { page }` → `PageLinks { width, height, links: Vec<PageLink { bounds, target }> }`. Bounds use the same upright page coordinates as text characters. `LinkTarget::Page { page, top }`, `Uri(String)` or `Unsupported`. Launch actions, links into other files, JavaScript and unresolved names are `Unsupported` and never followed. Caps: 4,096 links per page, 4,096 bytes per URI. An unreadable annotation is skipped, not fatal.
- **D2 — Links load with the page text.** The view asks for a page's links when it asks for its text (visible pages and their neighbours) and caches them with the text. No link request runs for a page that is not near the view.
- **D3 — Mouse.** Over a link the cursor becomes a pointing hand and a tooltip names the target after the usual tooltip delay: "Page 12" or the URI (middle-truncated at 80 characters). `Unsupported` links show "This link type is not followed" and do nothing on click.
- **D4 — Following a link.**
  - Internal: go to the page; when `top` is known, scroll so that `top` sits near the top of the view. The previous position goes on a back stack.
  - URI: `http`, `https` and `mailto` open with the system handler. Any other scheme does not open; a notice says "Not opened: <scheme> links". No confirmation for the three allowed schemes.
- **D5 — Keyboard.** Tab and Shift+Tab move a focus ring through the links on the visible pages in reading order (top to bottom, then left to right); Enter follows the focused link. Alt+← goes back and Alt+→ forward through the link and outline jumps (a stack of up to 50 positions per open document). Esc clears the link focus. These keys are checked against the PDF view's keymap context before the UI atom starts.
- **D6 — Outline.** `Request::Outline` → `Outline { items: Vec<OutlineItem { title, level, target: LinkTarget }> }`, flattened in document order with a nesting level. Caps: 10,000 items, titles cut at 512 characters, level at most 16. The Outline tab lists the items indented by level, with the page number at the end; Enter or click follows the target like D4 and pushes the back stack. The current chapter is highlighted while scrolling. A document without an outline keeps a short note in the tab: "This PDF has no outline. Use Pages, or Find to jump to a heading."
- **D7 — Text** goes into `viewer.ftl` (D59).

## Done when

- An internal link and an outline entry go to the right page and position, Alt+← comes back.
- A web link opens the browser; a `file:` or `javascript:` link does not.
- Tab reaches every link on the visible pages; Enter follows it.
- Gate, Windows CI and the owner's check on the work PC pass.
