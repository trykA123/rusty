# P15 · Viewer foundation: modes, languages, encodings, search marks, rich views

Status: running · Repo: `<repo>` · Branch: `p15-viewer` · Started: 2026-10-15

## Goal

The owner wants F3 to be one of Ferrite's strongest parts (the owner asked for very broad view support). After P15, F3 opens anything:
- text and code in far more languages than Notepad++, including Notepad++'s own UDL files;
- any encoding;
- images, JSON/YAML/XML as trees, CSV as tables, rendered Markdown, archive contents and fonts.

Search counts matches and keeps coloured marks per file. P16 adds the automotive formats on top of the viewer kinds built here.

Inputs: owner test notes (2026-10-15), the Notepad++ research (94 built-in languages, about 400 community UDLs, encoding detection order, Mark styles, Count, Find All, bookmarks, document map, tail -f), and audit findings 4 and 6 (`plans/2026-10-15-audit.md`).

## Decisions

- **D1 — Viewer kinds.** A `ViewerKind` registry in `rusty-ui` is the first piece of the module system (D13). Each kind has an id, a name, a sniff function `(head bytes, extension) → score`, and a view.
  - Built-in kinds: text, hex, image, tree, table, markdown, archive, font.
  - The highest score opens. Number keys switch between kinds that accept the file: 1 text, 3 hex, 5 rich (image, tree, table, markdown, archive or font, whichever fits). Alt+number does the same while editing.
  - The kinds list shows in the bottom bar.
- **D2 — Read-only by default, Lister keys.**
  - F3 opens read-only. Ctrl+E switches text up to 16 MB to editing.
  - In the viewer: F3 or Enter finds next, Shift+F3 finds previous, Esc closes, `n` and `p` open the next and previous file in the folder.
  - Ctrl+S saves only in edit mode.
- **D3 — Never on the UI thread** (audit 6). The `pick`, `read`, `paged` and `write` hooks run on the background executor with a 2 s "still opening…" state. Paged rows draw only from a cache that a background task fills.
- **D4 — Real paths** (audit 4). The app's file hooks use `rusty_fs`'s OS path conversion (verbatim prefix, lossless names), so `report.` is never confused with `report`.
- **D5 — Encodings.** Detection order, as in Notepad++:
  1. BOM;
  2. XML or HTML declaration;
  3. valid UTF-8;
  4. `chardetng` guess;
  5. the Windows ANSI code page.

  A declaration that names a single-byte encoding loses to valid UTF-8 with non-ASCII bytes: the file opens as UTF-8.

  Decoding uses `encoding_rs`. UTF-16 LE/BE opens (it is refused today). The encoding shows in the header and can be changed from a picker. A file that would not round-trip opens read-only.
- **D6 — Languages.**
  - **Extra grammars.** Compiled-in tree-sitter grammars are registered in gpui-component's `LanguageRegistry`, as many as build cleanly. Priority order: XML (with xaml, svg, plist, csproj, arxml and friends), SQL, PowerShell, INI and properties/conf, batch, Dockerfile, JSON/JSON5/JSONC, R, Perl, LaTeX, Objective-C, VB and VBS, linker scripts, TRACE32 `.cmm`, assembly.
  - **Detection.** Extension map, plus content sniffing (`<?xml`, shebang lines, first-line hints).
  - **Rule lexer.** For languages without a grammar (m4, OIL, DCM and others): keywords, line and block comments, strings, numbers and operators, from TOML rules. It also imports Notepad++ UDL XML files, so the community's ~400 languages work.
  - **Large files.** Paged text over 16 MB gets the rule lexer on the visible rows only.
- **D7 — Search and marks.**
  - **Find.** Find counts all matches in the background ("3 of 1,248").
  - **Find All.** A panel lists every matching line; Enter jumps there.
  - **Marks.** Any search can become a mark in one of 8 colours from a palette. Marks and recent searches are saved per file in `rusty.db` (keyed by path; stale when size and mtime change) and come back on reopen. Recent searches can be reused on any file.
  - **Overview.** Coloured ticks on the scrollbar show where marks fall.
  - **Navigation and display.** Bookmarks (Ctrl+F2 toggle, F2 next); show line endings; Follow mode (tail -f) for growing logs.
- **D8 — Images.** PNG, JPEG, GIF, WebP, BMP, ICO, TIFF and SVG, through GPUI's image support and the `image` crate. Fit, 100 %, zoom and pan, next and previous image in the folder, and basic EXIF (`kamadak-exif`).
- **D9 — Structured views.**
  - **Tree.** JSON, YAML and XML as a collapsible, virtualised tree, with the path of the selected node copyable. XML over 16 MB uses a streaming index (`quick-xml`), so ARXML of hundreds of MB opens.
  - **Table.** CSV and TSV, with the delimiter sniffed, virtualised (`csv` crate).
  - **Markdown.** Our own renderer (A7c): one linear pass over pulldown-cmark events into flat blocks, drawn as a virtualised list. No HTML or math. Caps: 1 MiB source, 200,000 blocks, 2,000,000 runs, 2,000 footnote lines; a pre-scan bounds table cells (over 1M cells, tables show as text). Past a cap the file opens as Text with a note.
- **D10 — Archives and fonts.**
  - **Archives.** Zip, tar (gz, xz, zst) and 7z contents are listed (name, size, packed size, date). Enter views an entry of up to 64 MB from memory.
  - **Fonts.** TTF, OTF and WOFF previews: sample text in several sizes and a glyph grid.
- **Out of scope:** PDF, Office documents and media players. They go to later modules.

- Searching `40 00` in a hex file shows the count, and a red mark survives closing and reopening the file.
- A PNG zooms and pans. A 200 MB ARXML opens as a tree. A CSV opens as a table. A zip lists its contents.
- The owner's two notes are covered: the viewer keys are always visible (done in `cfaefd2`), and the sort headers no longer shift.
- `cargo xtask gate` and Windows CI are green, and the reviewer passes the branch.
