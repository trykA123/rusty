# Beta battle plan · v0.9

Status: running (B1 waits for B0; B2 built, in integration; B3–B5 atomised; Q1–Q3 and Q5–Q11 open, architect defaults apply until answered) · Repo: `rusty` · Branch: `beta-bN-<atom>` per atom · Started: 2026-10-27

## Goal

Navo becomes safe, configurable and pleasant for daily work on Windows. A mistaken Shift+Del or overwrite can be undone for days. The window works at any width. Automotive and embedded files open in calm, rich viewers. Workspaces, tiled panes, find files and a preview pane make daily work faster. Modules, themes and keys become the user's choice. Each milestone below ships on its own as a GitHub pre-release.

Sources: roadmap "Right after the alpha" and "v1 Beta"; D13, D14, D16, D21, D58, D65, D68, D72–D81; P38 A5/A6; P43; `docs/retention.md` and the plans on `backend/beta-retention-on-main`.

## What exists today (checked at `6873ea06` and `backend/beta-retention-on-main` at `670250a5`)

- **Retention engine, not yet on main.** `rusty-retention` (capture, restore, purge, reconcile, adopt, bounded maintenance), `rusty-store::RetentionCatalog` (schema V7, `list_after` paging) and `[retention]` settings (`retain-deletes`, `retain-overwrites`, `days`, `max-volume-mib`, `min-free-mib`; both flags default `false`). Everything runs only with `--experimental-retention` (`rusty-app/src/cli.rs:80`, `gui.rs:338-346`). Missing for users: activation, settings UI, Recently deleted, Ctrl+Z restore, periodic maintenance, terminal metadata pruning, native Windows runtime checks. Containers still use `.ferrite-retained-*` names.
- **Undo** exists for rename jobs only: `UndoOffer` (`rusty-ui/src/browser/rename_batch/hooks.rs:10`) and `window_view/undo.rs`.
- **Fonts.** `rusty-ui/fonts/` bundles Archivo and JetBrains Mono. `tokens/design_b.rs` sets `ui_font` and `numbers_font` to Archivo. Inter and Space Grotesk are not bundled. The `appearance.font` and `appearance.font-size` settings exist (default Inter, 13) but nothing applies them.
- **Layout.** Two panes in one `Splitter` (`window_view/layout.rs`). No minimum window size (`title_bar/mod.rs:37`). Header and row cells compute widths in separate code (`file_list/header.rs`, `file_list/row.rs`). `ListParts` hides columns only by user choice. Tabs never overflow (`primitives/tabs.rs`). `test_window::open_sized` already opens a test window at a given width.
- **Settings sheet** is hand-written: `Section` and `Field` enums and four `FieldSpec` tables (`rusty-ui/src/settings/fields.rs`). No module schemas. `rusty-plugins` is an empty crate.
- **Shortcuts.** A user keymap with live reload and a Shortcuts page exist (`window_view/user_keymap.rs`, `settings_sheet/shortcuts.rs`, P20 done).
- **Automotive.** DBC and A2L scanners and converters exist in `rusty-automotive`; there are no viewer screens. Rich ELF/MAP is merged; CSV and CAN trace column resizing (P38 A5/A6) is not.
- **Background work.** P43 is written and its Q1–Q3 were accepted; only J0 ran. `IoQueue` never classifies a volume.
- **Not present:** workspaces, refresh mode per location, module registry, safe mode, ignore list, copy rules, custom colour or icon themes, soak test, spreadsheet viewer, NSIS installer.

## Decisions

Final for this plan. A worker that finds one wrong stops and reports.

- D1 — **Milestone = pre-release.** Each milestone merges as squash commits, passes the full gate and Windows CI, and the `deployer` publishes a pre-release `beta-<date>` with the exe and zip. The owner checks it on the work PC before the next milestone's last atom merges.
- D2 — **Retention is on for everyone.** The `--experimental-retention` flag goes away. Coordinated mode (mutation leases, private-path protection) is the only mode. `--no-retention` starts without leases and without retaining, as a safe-mode escape; it keeps the reserved-folder protection (retention plan D4). One-instance requests must match, as today.
- D3 — **Volumes that cannot retain fall back openly.** When the target provider has no atomic rename or no file identity (network shares, some USB file systems), Shift+Del shows the ordinary permanent-delete confirmation with one more line: "This drive cannot keep deleted files." It never refuses and never retains silently.
- D4 — **Recently deleted is a side sheet** on the existing `side_sheet` (like Settings), opened by the command `files.recently-deleted` (Ctrl+K and the File menu). It lists retained entries newest first. Restore returns an entry to its original path; on a collision it keeps both with " (restored)" added. "Delete now" purges one entry after a confirmation. Its visual direction comes from designer round R1.
- D5 — **Ctrl+Z after a retained delete or overwrite restores it.** `UndoOffer` gains a kind: `Rename` (today) or `Retained(Vec<RetentionId>)`. The undo confirmation names the count and the folder, as rename undo does.
- D6 — **Maintenance runs on a timer, too.** Bounded maintenance runs once after start-up recovery and then every 6 hours, on a worker, holding the mutation lease, at most 32 purges per pass (the existing per-job bound).
- D7 — **Fonts (D78).** Inter for the interface and numbers (tabular numerals), JetBrains Mono for paths, viewers and hex, Space Grotesk SemiBold for the wordmark, window titles and sheet titles. Archivo is removed. Font files come from the official releases (Inter 4.1 `rsms/inter`, Space Grotesk 2.0.0 `floriankarsten/space-grotesk`), with their OFL licence files beside them. The `appearance.font` and `appearance.font-size` settings apply live.
- D8 — **Responsive layout (D80 1–6).** Minimum window size 480 × 360 px. Header and row cells take their widths from one function. Names end in an ellipsis; Ext, Size and Date are fixed width. Columns drop automatically in the order Ext, Date, Size when the pane is too narrow; this never changes the user's View setting. Below 900 px window width the window shows one pane (Q3). Tabs shrink to a minimum width, then the rest move into a "+N" overflow menu. Layout tests render at 480, 800 and 1280 px and run in the normal nextest step of the gate.
- D9 — **Tiling panes wait for their design round.** No tiling code starts before the owner picks a direction (R7) and its plan is written. The core layout tree already splits, closes and focuses panes; the plan builds on it.
- D10 — **Models (owner, 2026-10-26).** The main workforce is Codex Sol 6.1 through crew: api-builder and ui-builder at medium, high where the table says so; checker on Sol 6.1 high. Opus 5.5 medium for senior, designer and reviewer-senior. Sonnet 5.5 medium only for trivial edits (patcher) and the documenter. Haiku only for scout lookups. Never Opus high. The B1 and B2 rows were written before this rule; B1 atoms run on the new models.
- D12 — **Order (D81).** The owner's priority items come first, grouped as B3–B6. The items moved into the beta from v1.0 and later follow as B7–B9. Every other beta item comes after them (B10–B16), including background work and Raw/Pretty, which the roadmap listed "right after the alpha".
- D13 — **Open a terminal here is a core command now.** `files.open_terminal` starts the configured terminal in the active pane's folder. It moves behind the module registry when B12 lands. Network and archive folders refuse with a status line.
- D14 — **Workspaces belong to a window (Q9).** Alt+1…9 switch the focused window between nine slots. A slot holds the layout, panes, tabs, history and split ratio, not listings. Switching saves the current slot first. An empty slot starts as a copy of the current layout. Slots are saved in the session file.
- D15 — **Accessibility basics, scope.** Narrator reads the file list rows, dialogs and Ctrl+K results with a role and a name. Every focusable element shows a focus ring. Every animation honours reduced motion. Windows contrast themes switch Navo to the system colours. A UI scale setting (80–200 %) applies live.
- D11 — **Checks.** Workers run `cargo xtask check -p <crate>` and the nextest filter in their row. The full `cargo xtask gate` runs once per milestone on the merge branch. One cargo build at a time (nice 10, `CARGO_BUILD_JOBS=8`).

#### S0 — Recently deleted, three directions

- **Change:** three genuinely different directions for the sheet: list rows (name, original folder, size, deleted when, expires in), grouping (by day, by volume or flat), Restore and Delete now, empty state, a drive that cannot retain, a volume over its cap. Calm by default (D58). Keys shown next to actions.
- **Check:** the prototype opens with a picker; both themes; 390 px and desktop screenshots looked at.
- **Stop if:** a direction needs data the catalog does not hold (`RetainedRow` fields above).

#### S1 — Retention on by default

- **Change:** `Start.experimental_retention` becomes `Start.retention`, default `true`. `--no-retention` sets it `false`. `--experimental-retention` is accepted and ignored for one release, with a log line. The one-instance request keeps its wire field name; a mismatch is still refused.
- **Check:** tests: no flag → `retention == true`; `--no-retention` → `false`; both flags → `false`; a mismatched second instance is refused.
- **Stop if:** any code path outside `cli.rs`, `main.rs` and the instance request reads the old field name.

#### S2 — Defaults

- **Change:** `RetentionData::default()` per Q1 (architect default: `retain_deletes = true`, `retain_overwrites = true`, `days = 3`, `max_volume_mib = 1024`, `min_free_mib = 256`). Update the snapshot.
- **Check:** settings tests pass; the snapshot diff shows only the two flags.

#### S3 — Drives that cannot retain

- **Change:** before building a retained delete plan, ask the target provider for `rename_atomic` and file identity support. Without them, build the ordinary permanent-delete plan and add the D3 line (`delete-cannot-retain`) to its confirmation. Overwrites on such drives keep today's behaviour and say nothing.
- **Check:** tests with `FakeFs` without atomic rename: confirmation shows the line; Cancel creates no job; a supporting provider still retains.
- **Stop if:** the provider capability is not reachable from the UI layer without a new hook; report the shape.

#### S4 — Contract for retained entries

- **Change:** new `rusty-ui/src/browser/retained.rs`: `RetainedRow { id: RetentionId, original: Location, kind, bytes: u64, deleted_at_ms: i64, expires_at_ms: i64, state: RetainedState }`, `RetainedState { Ready, Busy, NeedsAttention }`, trait `RetainedHooks: Send + Sync { fn list(&self, after: Option<RetentionId>, limit: u16) -> Result<Vec<RetainedRow>, String>; fn restore(&self, id) -> Result<Location, String>; fn purge(&self, id) -> Result<(), String>; }`. A `NoRetained` default that returns empty lists.
- **Check:** crate check; `NoRetained` lists nothing.

#### S5 — Hooks in the app

- **Change:** `rusty-app/src/retained_hooks.rs` implements S4 on `Vault` and `RetentionCatalog`. Every call runs off the UI thread and takes the exclusive mutation lease. `restore` targets the original path; on a collision it uses the " (restored)" name (D4). Errors are Fluent strings. Wire it into `gui.rs` next to the rename hooks.
- **Check:** tests on a temp profile: list pages in id order; restore to a free path; restore with a collision keeps both; purge of a pinned entry refuses with a message; a running job's entry shows `Busy`.
- **Stop if:** `Vault` cannot be shared with the job engine's instance (one `retention.lock` per profile); report before adding a second owner.

#### S6 — Ctrl+Z restores

- **Change:** `UndoOffer` gets `kind`. A finished retained delete or overwrite job sets `Retained(ids)`. `undo_last` calls `RetainedHooks::restore` per id and reports partial results in the status line.
- **Check:** tests: Shift+Del then Ctrl+Z restores both files; a rename undo still works; an entry purged in between is reported, the rest restored.

#### S7 — Maintenance timer

- **Change:** run `maintain_volume` for each volume with live entries once after start-up recovery, then every 6 hours, on a background thread with the lease and the existing bounds. Skip while a job holds the lease; try again in 10 minutes.
- **Check:** tests with an injected clock: start-up pass runs; a 6 h tick runs; a held lease defers.

#### S8 — Prune terminal rows

- **Change:** delete `Restored`, `Purged` and `Aborted` rows whose container cleanup is acknowledged and whose terminal time is older than 30 days, at most 1,000 per call, in one short transaction. Called from the S7 pass.
- **Check:** tests: old acknowledged rows go; unacknowledged and live rows stay; a job referenced by a live row is never pruned.

#### S9 — The sheet

- **Change:** the picked R1 direction on `side_sheet`. Up and Down move, Enter restores, Delete asks and purges, Esc closes. Pages of 200 rows load on scroll through `RetainedHooks::list`. Calls run off the UI thread.
- **Check:** headless tests: rows render from a fake hook; Enter calls restore; Delete opens the confirmation; empty state text.
- **Stop if:** the side sheet cannot host a virtual list; report.

#### S10 — Command and wiring

- **Change:** `files.recently-deleted` in the registry, the File menu and Ctrl+K; no default key. Opens the S9 sheet with the app's hooks. Update the command snapshots.

## Later milestones

### B6 · Tiled panes

### B11 · Undo anything

Every job step becomes reversible, compensable or final (journal and recovery exist). Undo offers only what it can do. A history list shows recent jobs with an Undo button each. Per-case confirmations: one switch per case (Recycle, permanent delete, overwrite, drop, large copy), each "ask / don't ask". Questions: how far back does history go (count or days)? Can a job be undone after a restart? What does undo of a copy do to files the user edited since? Does undo of a Recycle Bin delete restore from the Recycle Bin? Design round R4.
