# P13 · Hex view and large files in F3

Status: done · Repo: `<repo>` · Branch: `p13-paged-view` (based on `p12-view-edit`) · Started: 2026-10-15

## Goal

Owner request (2026-10-15): F3 opens any file, whatever its extension (`.exe`, `.elf`, `.dll`, …) or size. Binary files show as hex. Text over 16 MB opens read-only in pages, so memory stays small however big the file is.

## Decisions

- D1 — **Three modes in one viewer.**
  - Text edit: the P12 editor, for text up to 16 MB.
  - Hex: any file, any size.
  - Paged text: read-only, for text over 16 MB, and for binary files when the owner switches them to text.
- D2 — **Mode on open.** A NUL byte or a UTF-16 BOM in the first 8 KB opens Hex. Text over 16 MB opens Paged text. Anything else opens Text edit. Alt+1 switches to text and Alt+3 to hex (Total Commander's Lister uses 1 and 3). Alt+1 on a small text file goes back to Text edit.
- D3 — **Pages, not the whole file.** Positional reads of 64 KB pages with an LRU of 32 pages (2 MB). Std's default share mode on Windows includes delete, so other panes can still rename or delete the open file. No memory map.
- D4 — **The view position is a byte offset, not a row number.**
  - Hex: rows of 16 bytes; row N starts at N × 16.
  - Paged text: a row is one line, ending at `\n` (a trailing `\r` is not shown). A line longer than 4096 bytes is cut into 4096-byte rows, each cut moved back to a UTF-8 character boundary.
  - The start of the row holding any offset is found by scanning back up to 64 KB for the line start, then stepping forward by rows. Past 64 KB without a newline, the scan's own start is used as the anchor.
  - The scrollbar maps `offset / length`, so scrolling works at once without an index.
- D5 — **Sparse line index, built in the background.** Every 1024th line start is recorded (about 1 MB of index for a 10 GB file). Line numbers and Ctrl+G (go to line) work for the part already indexed; the header shows indexing progress.
- D6 — **Search in the background.** Text (ASCII case-insensitive unless "match case" is on) or, in Hex, bytes like `4D 5A` or `4d5a`. 1 MB chunks overlapping by the needle length − 1, with progress, cancelled by Esc. Enter finds the next match, Shift+Enter the previous; no wrap ("Not found below.").
- D7 — **A file that changes on disk** (length or modified time, checked on each page miss) drops the cache and takes the new length. The header says "Changed on disk". A growing log can be followed by pressing Ctrl+End again.
- D8 — **Executable summary.** In Hex, a PE, ELF or Mach-O file gets one header line (format, bits, machine, kind: program, DLL or shared library, object). It is read by hand from the first 4 KB (no parser crate: the few header fields are simple and `goblin` rejects short Mach-O headers).
- D9 — **Keys in the paged views:** arrows, PgUp/PgDn, Ctrl+Home/End, mouse wheel, scrollbar drag, Left/Right scroll sideways by 8 columns in Paged text, Ctrl+F search, Ctrl+G go to a line (text) or a hex offset (hex), Esc closes the search bar and then the viewer, and F3 closes. Selection and copy come later.
- New dependencies: `memchr` 2.8 and `aho-corasick` 1.1 in `rusty-core`. Both are MIT/Apache and cross-platform.

## Done when

- A 2 GB file of random bytes opens in Hex at once, scrolls to the end with Ctrl+End, and the process stays under 100 MB of private memory.
- A 1 GB text log opens in Paged text, shows line numbers as indexing proceeds, and finds a word near the end with a progress line.
- An `.exe` or `.dll` shows its PE summary line.
- The open file can be renamed from the other pane while it is open (Windows CI test).
- `cargo xtask gate` and Windows CI are green, and the reviewer passes the branch.

  - `row_start_at` stops when a row makes no progress, so a file that shrinks while open cannot hang the UI.
  - The look-back window ends one byte after the offset, so inside lines over 64 KB Up and PgUp move by whole rows and Ctrl+End shows a full last row. Past 64 KB the cut grid is the window's own (rows stay contiguous and ≤ 4 KB; it may differ from the grid seen scrolling down from the line start).
  - The line index also marks every 1 MB, at line starts and inside long lines, so a line number or a Ctrl+G lookup reads at most about 1 MB. The header's line count is computed once when indexing ends.
  - Reading past the end re-checks the file, so a growing log with its tail cached is noticed (Ctrl+End again follows it).
  - A CRLF right after a full 4096-byte row ends that row.
  - A failed index shows its error and no stale "Indexing…" percentage.
- 2026-10-15 — Review round 2: PASS WITH FIXES, fixed with tests:
  - When no line start lies within 64 KB, `previous_row` takes the row ending exactly at the current start (4 KB back, moved forward to a character boundary), so Up, PgUp and Ctrl+End move whole rows in non-ASCII text too. `row_start_at` past the end is the row before the end.
  - `line_start` for a line past the last newline returns None without reading.
  - A 4097-byte tail is cut at 4096 bytes.
  - Reading past the end re-checks the file at most every 250 ms (network shares).
