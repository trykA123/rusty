# P20 · Shortcuts the user can change (D49)

Status: ready · Repo: `<repo>` · Branch: `p20-kN` per atom · Started: —

## Goal

Every action has a default shortcut, and the user can change any of them. Folding the JSON, YAML and XML tree uses Ctrl and Alt chords, so it no longer depends on bare keys only. The built-in shortcuts are data, a user `keymap.toml` overrides them, and the settings sheet has a shortcuts page that records a key and shows conflicts.

## Decisions

All decided (D49, D6, D13, architecture "Settings and keymaps"); workers never reopen them.

- **D1 — Tree chords.** Alt+Right / Alt+Left open or close the node with everything under it. Ctrl+Shift+Right / Ctrl+Shift+Left open or close the whole tree. Ctrl+1…Ctrl+9 show the tree to that depth (depth 1 = only the root's children). `*` and `-` stay as extras. Opening everything stays bounded by the tree's existing row limits and never blocks the UI.
- **D2 — Command names.** Every GPUI action gets one stable name in `area.verb` form (`tree.expand_all`, `pane.copy_path`), a label and a context. The names are the only thing the keymap, the palette, menus and plugins refer to (D6).
- **D3 — Keymap as data.** The built-in keymap is one embedded TOML file; `bind_keys` functions read it instead of hard-coding keys. The F-key bar and the menus show the keys from the active keymap.
- **D4 — User keymap.** `keymap.toml` in the settings folder holds only the user's changes. It is validated on load; unknown names, bad keys and conflicts are reported in the status line and diagnostics; an invalid file is never overwritten and the last valid keymap keeps running; changes apply live. A key can be unbound.
- **D5 — Shortcuts page.** A page in the settings sheet (P19 L6) lists every command with its keys, searchable by name or key; Enter records a new key, a conflict is shown before it is saved, and each row resets to its default. It writes `keymap.toml`.
- **D6 — Total Commander keymap.** Later, as a data package (roadmap); not in this plan.
