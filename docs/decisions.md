| D6 | 2026-10-13 | One typed command system: every action has one name and one implementation (`path.copy`, `files.recycle`); shortcuts, menus, the palette, macros and plugins all call those names | Accepted (explained 2026-10-13; reopen if needed) |
| D7 | 2026-10-13 | Delete goes to the Recycle Bin. **Shift+Del deletes permanently after a warning** that shows how many items, their total size and the first paths. Every file operation is planned before it runs | Decided |
| D8 | 2026-10-13 | No scripting language in v1; macros are sequences of commands. **Choose a scripting language after v1**; owner leans to **Lua** | Decided; Lua likely |
| D9 | 2026-10-13 | Global search uses Everything. If it is missing, Rusty offers to install it through an **Everything plugin** that downloads the official installer from voidtools with a checksum check, only after the user agrees. Bundling terms to confirm with voidtools' licence. Own NTFS index later | Superseded by D23 |
| D10 | 2026-10-13 | Portable mode when `rusty.toml` sits next to the executable | Decided |
| D11 | 2026-10-13 | Global search without Everything: Rusty's own index. Fast path: an optional admin helper service reads the NTFS file table and change journal and serves the unelevated app over a local pipe (names only, no file access). Fallback: parallel drive walk saved to disk and kept current by watchers (also used for network drives). Optional extra source: Windows Search. Matching with `nucleo`; memory budget about 80–100 MB per 2 million files | Decided |
| D12 | 2026-10-13 | Code signing for builds used on the work PC; portable `.exe` plus an installer (installer details later) | Decided (owner: “Ok”) |
| D13 | 2026-10-14 | **Modular app: a small core, every other feature a module.** The core is always on: state and commands, panes, tabs, layout, workspaces, the file list, the job engine and its safety checks, settings, pins, the Ctrl+K palette, shortcuts and the module host. Modules are native (compiled in, can be turned off at runtime), WASM (third party, sandboxed) or data packages (themes, keymaps). One manifest and one registry for all three; modules talk only through commands, events and declared services. No third-party native DLLs | Decided |
| D14 | 2026-10-14 | **v1 is small, stable and light.** Scope and phases in [roadmap.md](roadmap.md). WASM plugins come after v1 (v2.0). English is the default and only language in v1; every string lives in Fluent files so other languages can follow | Decided |
| D15 | 2026-10-14 | **Total Commander selection model by default:** Space selects and sizes folders, Insert selects and moves down, a short right-click selects, right-drag selects a range, a long right-click (about 400 ms) opens the native Windows context menu with Rusty's actions on top. One setting switches to the Explorer model | Decided |
| D16 | 2026-10-14 | **Theming like Zed:** built-in light and dark that follow Windows; user colour themes in TOML (families with light and dark variants, live reload, contrast check); separate icon themes (SVG by extension, name and folder, with shell icons kept for `.exe`, `.lnk`, `.ico`). Themes and icon themes are data packages | Decided |
| D17 | 2026-10-14 | **Storage:** settings stay in TOML; the session snapshot is `postcard` and carries the visible rows so the first frame opens no database; **SQLite (`rusqlite`, bundled) from the Foundation phase** for user data and journals (`rusty.db`) and for caches (`cache.db`, safe to delete); the global index uses its own memory-mapped format | Decided |
| D18 | 2026-10-14 | **No Tokio in the core.** GPUI executors for UI and pane tasks, the job engine's own thread pool for file operations, `rayon` for CPU work. A module that needs async networking may start its own runtime on first use | Decided |
| D19 | 2026-10-14 | **Drives and network locations in the core:** a Total Commander-style drive bar (mapped network drives marked, disconnected ones dimmed and reconnectable), Alt+F1 drive menu, UNC paths everywhere, network reads off the UI thread with timeouts and an offline state, refresh mode per network location | Decided |
| D20 | 2026-10-14 | **Diagnostics from the Foundation phase:** a `rusty-diag` crate with redacted structured logs, an event ring, memory and performance statistics, and a diagnostic report the user saves by hand. Redaction happens at record time through typed fields and is enforced by a canary test. Raw memory dumps are opt-in, local and short-lived. No telemetry | Decided |
| D21 | 2026-10-14 | **Core foundations from day one:** locations through providers instead of raw paths, serialisable commands, record and replay, a fake file system with fault injection, a hostile-name corpus, one error model with recovery actions, an I/O queue per volume, multi-window state, experimental flags, key contexts. Small core features: Explorer clipboard, lock owner in errors, command line, per-monitor DPI, accessibility basics, optional default file manager | Decided |
| D22 | 2026-10-14 | **Copy modes in the core:** Auto (default), Standard, Parallel and Large files, all on the same safe job engine; per-job options (verify, conflicts, what to keep, I/O priority, bandwidth limit, queue), named copy profiles and rules by destination. No external `robocopy.exe` in the core | Decided |
| D23 | 2026-10-14 | **Rusty's own index is the main global search**, built like Everything: `rusty-indexd`, a Windows service, reads the NTFS MFT and follows the USN journal; names and parents in compact memory, parallel substring, wildcard and regex search plus fuzzy ranking in Ctrl+K; filter syntax (`ext:`, `size:`, `dm:`, `path:`). Fallback for non-NTFS, network drives or a blocked service: parallel walk plus watchers. The engine is built alongside Alpha and ships in v1.1, or in Beta if ready. Everything becomes an optional module for people who already run it. The owner runs Everything with its service at work, so a service is expected to be allowed there | Decided |
| D24 | 2026-10-14 | **Rusty as a Framework laptop:** modules are expansion cards in slots. New slots: metadata provider (one source for columns, sorting, filters and search syntax), view mode, transform (output through the job engine), automation rule (runs commands through plans), status and drive badges. Curated **module packs** (Developer, Photo, Homelab) install a coherent set with permissions shown first | Decided |
| D25 | 2026-10-14 | **Reusable UI components from the first screen**, on `gpui-kit` (which pins GPUI and adds AccessKit accessibility and headless UI tests). Four layers: tokens, primitives that wrap `gpui-kit`, Rusty components (props in, commands out), views. The app never imports `gpui-kit` directly; plugin widgets are a subset of the same components; a component gallery is the review and test surface. `gpui-shell` (JavaScript) is not used | Decided |
